# 第一轮内测计划

> 5–10 位破产管理人，邀请制，人工发码。
> 2026-08-08 拟。执行中如与本文不符，以罗师傅现场判断为准。

---

## 一、这一轮只回答两个问题

5–10 位真管理人是极稀缺的资源。**最容易犯的错是把这一轮当"全面测试"**——
让他们去踩我们自己已经查清楚的缺陷（见 §四），除了消耗他的耐心和你的人情，
不产生任何新信息。

所以这一轮只回答：

**Q1 —— 他愿不愿意把真实案件材料传上来。**

这是产品能不能跑起来的前提。破产材料涉当事人隐私、涉商业秘密，管理人自身有
保密义务。如果他不敢传，后面所有功能都是空的。这个问题只能用真人真案子回答，
问卷问不出来（所有人都会说"愿意"）。

**Q2 —— AI 出的东西，他敢不敢往下用。**

不是"准不准"——准确率是我们自己该测的，不该消耗内测名额。是**"他看完之后，
会不会把它当成工作的起点"**：把结论复制走了，还是关掉窗口自己重做一遍。
这个行为差别，就是产品有没有价值。

其余一切（好不好看、快不快、有没有 bug）这一轮都是次要的。

### 明确不做的

- 不做功能全覆盖测试
- 不发问卷（5–10 个人发问卷是浪费）
- 不追求"零 bug 才上"——§四那些已知缺陷带着上，出现了照实说
- 不在这一轮验证准确率

## 二、上线前的硬门

### 🟥 H-1　会议纪要的跨用户越权（**已派给另一个 session 处理**，上线前需确认完成）

`meeting_records` 表**没有归属列**——核实位置
`deep-nirvana/packages/infra/src/deepnirvana_infra/db/models.py` 的
`MeetingRecordRecord`，没有 `user_id` / `owner_id` / `created_by` 任何一个。

后果：**任何一个登录的内测用户，能读到全库所有人的会议纪要和录音。**

这一轮的用户分属不同律所、互为同业竞争、手上是不同案件。A 所翻到 B 所的会议
录音，不是 bug，是事故——而且是一旦发生就没法挽回信任的那种。

修复在分支 `fix/meeting-auth-p0`，**尚未合入 main**。

罗师傅 2026-08-08 已把这条派给另一个 session 处理，本文不再重复安排。
**但它仍是上线硬门**——放人之前要拿到「已修复且已验证」的确认，不能默认它好了。
验收口径：用 B 账号去读 A 的会议纪要，应当返回 404，且与「不存在」的响应逐字节相同
（不能是 403——403 本身就泄露了"这条记录存在"）。

### 🟥 H-2　涉密企业破产的上传闸门

定密材料禁止在非涉密信息系统处理，公有云 SaaS 一律不行
（《保守国家秘密法》第 31 条第(三)项，2024-05-01 施行）。军工、涉密院所、
部分国企破产是真实场景。

做法很小：材料上传前一个**不可跳过的单选**——"债务人是否涉密单位／材料是否
含国家秘密"，选"是"直接阻断上传。用户协议里同时写成用户承诺条款。

工作量最小、后果最重，全部合规动作里排第一。

### 🟨 H-3　落地页与产品分域

落地页静态直出，产品在登录墙后，两个子域，nginx 分流。产品域上还要挡掉
`/api/dn/admin/`、`/admin/`、`/docs`、`/redoc`、`/openapi.json`
（FastAPI 建实例时没传 `docs_url=None`，这三个默认全开）。

### 🟨 H-4　按 IP 限流现在是死的

`deep-nirvana/apps/api/src/deepnirvana_api/account/invite_http_utils.py` 的
`extract_client_ip` 注释自陈：无反向代理、vite 不注入 XFF，取到的 IP
**恒为 `127.0.0.1`**。上公网前必须先在 nginx 配好 XFF 且服务端只信任反代那一跳，
否则要么全世界算同一个 IP（第 N 个用户看到 429，像功能坏了），要么加个 header
就换一个限流 key，形同虚设。

## 三、放人节奏：分批，别一次放满

**第一批 2–3 人**（关系最近的）。理由：如果有个基础问题——登录进不去、材料传
不上、答案出不来——2 个人的第一印象毁了还能补救，10 个人一起毁就没了。

跑顺了再放剩下的。设计稿里那句话就是这一轮的调子：

> 人不多，我们一位一位聊。

发码走 admin 后台人工勾选，不自动发。落地页收上来的是线索池，不是准入通道。

## 四、已知缺陷对照表

**用户撞上时你知道这是已知项，不必慌，也不要临时改。** 照实说"这个我们知道，
在修"，比支支吾吾可信得多。

| 现象 | 真相 | 位置 |
|---|---|---|
| 逐条置信度徽标永远显示「置信度未知」 | 前端写了完整高/中/低徽标，后端数据模型里没有这个字段 | 前端有 UI、后端无字段 |
| 换设备或清缓存后，依据面板一片空 | 依据面板存在浏览器本地；服务端回放只给回问题原文、答案正文和编号 | — |
| 法条引证点不出外部原文 | 法规库里 statute 类原文链接非空率为 0，外链按钮不渲染（fail-safe，不是崩）。能用的是**就地展开**正文 | `AgentConsole.tsx:2824` `resolveEvidenceOriginalHref` |
| 文书复核轨迹重启后消失 | 谁何时复核、打回理由、分派对象、批注，全在进程内存，API 一重启清零，导出的审核日志 CSV 也随之变空 | `bankruptcy_documents/server.py:157-170` |

## 五、收反馈：访谈，每人 20 分钟

用完之后当面或电话，问三件事，其余顺其自然：

1. **你拿它做的第一件事是什么？**
   暴露真实动机。往往和我们设想的不一样，这是这一轮最可能出现的意外收获。

2. **有没有哪一刻你不信它？具体是哪句话？**
   这是 Q2「敢不敢用」的直接证据。要追到具体那一句，"整体感觉还行"没有信息量。

3. **如果明天它没了，你会不会想它？**
   唯一诚实的价值问题。客气话在这个问题上很难说圆。

不要问"你觉得还需要什么功能"——用户答的永远是他能想到的现成东西，
而且会把访谈引向功能清单，偏离这一轮的两个问题。

## 六、这一轮什么时候结束

**不按时间，按问题回答清楚了**：

- [ ] 至少 3 人传过**真实案件材料**（不是测试文件）
- [ ] 至少 1 人把 AI 输出用进了**真实工作产物**
- [ ] Q1 / Q2 各有明确答案

答案是否定的也算结束——**「管理人不敢传真实材料」是极有价值的结论**，
它说明下一步该做的是私有化部署，而不是继续加功能。

## 七、这一轮不承诺的事

落地页文案已按此口径写过一轮，执行时别加回来：

- 不承诺"逐份审核、通过或不通过都短信回你"（码实际给熟人，兑现不了）
- 不承诺名额（首批只有 5–10 位，优先给正在使用优破案的机构，这句已经写在页面上）

- 不说私有化部署已可交付——仓里没有任何可交付的部署产物
